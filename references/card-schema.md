# 八字段卡片与制卡规范

## 固定字段

字段顺序必须是：

```text
Front / Back / Extra / Mistake / Trigger / Importance / Source / Tags
```

- `Front`：单一、具体的主动回忆问题。
- `Back`：足以独立评分的完整答案。
- `Extra`：知识框架位置或紧密相关的二级结论。
- `Mistake`：最可能的混淆、错误推理、单位错误或适用边界。
- `Trigger`：题目出现什么条件、措辞或场景时应调用该知识。
- `Importance`：`必背`、`高频`、`易错`、`理解`、`低频补充` 之一。
- `Source`：课程、章节、小节、文件，能确定时附页码。
- `Tags`：至少包含科目和章节的 `::` 层级标签，并包含重要程度。

## 制卡原则

- 一张卡只设置一个主要回忆目标。
- Back 必须包含问题所要求的所有关键条件和结论。
- 内容强关联时保持在一张卡内，例如完整比较表、固定流程或公式与条件。
- 独立回忆确有价值时再拆卡，例如同一算法的目的、步骤、复杂度和失效边界。
- 不按段落或笔记条目机械生成卡片。
- 不用卡片数量作为知识密度指标。

## 典型卡片

- 定义卡：对象、定义、必要限定。
- 结构卡：组成部分及各自功能。
- 流程卡：触发条件、步骤顺序、结果。
- 对比卡：对象、共同维度、关键区别、适用场景。
- 公式卡：公式、变量、单位、条件和常见代入错误。
- 算法卡：核心思想、步骤、复杂度、稳定性或边界。
- 易错卡：错误说法、错因、正确边界。

## 禁止正面

- “本节第 N 个知识点是什么？”
- “请回忆上述内容。”
- “这是什么？”
- 只复制一段陈述而没有明确提问。
- 依赖卡片顺序、教材位置或上一张卡才能理解的问题。
- 同时询问多个互不相关对象的超载问题。

## 公式

- Anki 行内公式使用 `\(...\)`，独立公式使用 `\[...\]`，或在打包前从 Markdown 定界符稳定转换。
- 不把未核实的 OCR 公式写入已验证答案。
- 公式卡必须说明符号、单位和成立条件；纯默写式公式卡只在确有背诵价值时使用。

## 稳定身份

- 模型 ID 和牌组 ID 由固定命名空间与牌组名稳定生成。
- GUID 由规范化 `Source + Front` 生成。
- 改写 Front 会改变卡片身份，因此无必要时不要只为文风重写已发布正面。
- 默认按章独立牌组；用户明确要求时才生成合并牌组。
