# 打印版生成与检查规范

## 输出边界

- `--output-dir` 必须精确为项目 `print/` 根目录，不允许其子目录。
- 禁止输出到 `source/`、`cleaned/`、`notes/`、`cards/`、`reports/`、`build/`、`assets/`，也禁止任意绝对外部目录和符号链接越界。
- 默认不覆盖同名 Markdown、DOCX 或 PDF。只有用户明确授权替换时才使用 `--force`。
- 版本通过 `--title` 和生成文件名管理；文件名应包含课程、范围或版本，不通过覆盖旧成品或建立输出子目录来管理版本。

## 标题与分页

- 全局文档标题只出现一次。
- 每章章标题只出现一次，并作为该章唯一 H1。
- 合并 Markdown 的首个 H1 已提供文档标题；Pandoc HTML 命令不得再传同名 title metadata，生成的 HTML 不得含 `title-block-header`。
- 分章笔记首个 H1 与章节标题、全局标题或笔记文件标题重复时移除；其他正文 H1 降为 H2。
- 章间分页只由 H1 的打印样式控制，不同时插入原始 `\newpage`，避免双重分页和异常空白页。
- 首章章首页和“本章知识主线”紧随首章标题，保持同一章起始，不额外分页。

## 章节开头

- 原教材存在思维导图或知识框架页时优先使用原页。
- 没有专门导图时使用原教材章首页，并补充“本章知识主线”。
- 生成的知识主线不得标为“原教材思维导图”。
- 图片必须属于对应章节，保持清晰、比例正确，不裁掉关键信息。

## 笔记图片

- 构建前解析每份分章笔记中的 Markdown 和 HTML 图片。
- 本地图片必须实际存在；按解析后的唯一文件计入 `预期图片数`，使 DOCX 审计能与 `word/media/` 核对。
- 同一文件被多次引用时按一个媒体文件计数，避免把引用次数误当 DOCX 媒体数。
- 远程 URL、缺失文件、空路径、带不可核验参数或无法解析的图片引用必须在 Pandoc 和 Chrome 渲染前失败。
- 自动嵌入成功不代表图片视觉正确，仍须逐页检查断图、缩放和裁切。

## 排版与公式

- 页面使用 A4，正文适合双面打印和连续背诵。
- 使用克制的正文色、标题色和风险强调色，不使用装饰性卡片、渐变、背景图或大面积色块。
- 正文字号不得为了压缩页数而影响打印阅读。
- 标题与其后内容保持在一起，列表换页不应造成项目符号与正文分离。
- DOCX 使用 Word 原生公式对象；PDF 使用 MathML 或经过验证的公式渲染方式。
- 生成前检查公式定界符；生成后检查裸露 `$`、`\frac`、`\begin`、`_{}` 和 `^{}`。
- OCR 存疑公式不得在打印版中伪装为已核实公式。

## 结构检查

- DOCX 是完整压缩包，包含 `word/document.xml`。
- DOCX 中媒体文件数不少于章首页和笔记本地图片的唯一文件总数。
- DOCX 中公式对象数不少于笔记中的预期公式数。
- PDF 每页尺寸为 A4，无异常空白页和裸露 LaTeX。
- DOCX 的 LibreOffice 渲染若受 macOS 中文字体影响，使用 Quick Look 或 Word 补充检查，并说明工具边界。

## 强制逐页视觉复核

最终 PDF 生成后，先渲染全部页面：

```bash
PROJECT_ROOT="/绝对路径/课程项目"
PRINT_PDF="$PROJECT_ROOT/print/课程名纯背诵笔记.pdf"
PRINT_QA_DIR="$PROJECT_ROOT/build/print-qa/本次版本"
PDF_SHA256="$(shasum -a 256 "$PRINT_PDF" | awk '{print $1}')"
mkdir -p "$PRINT_QA_DIR"
pdftoppm -png -r 160 "$PRINT_PDF" "$PRINT_QA_DIR/page"
```

当前代理必须列出全部渲染页，并对每一页调用 `view_image`。逐页检查：

- 断图、图片缺失、错误裁切或比例异常。
- 中文缺字、乱码、字体回退和字符被截断。
- 标题、正文、公式、表格或图片重叠。
- 内容越界、页边距异常和列表断裂。
- 异常空白页、重复标题、双分页和章节跳转错误。
- 裸露公式源码、原样输出的 `{width=...}` 和未替换占位符。

检查结果写入 `reports/打印视觉复核.tsv`，表头固定为：

```text
PDF_SHA256 / 页码 / 状态 / 问题
```

PDF 每一页必须恰有一条记录，每一页都重复填写当前 PDF 的同一 `PDF_SHA256`。`状态` 使用 `已通过` 或 `有问题`；`有问题` 时填写具体位置和现象。修复后重新生成、重新计算 SHA-256、重新渲染并从第一页复核。自动渲染不等于视觉通过。

视觉复核表完成后，才运行 `audit_outputs.py`。只有结构审计、全页记录和当前代理实际逐页观察都通过，才能说打印版通过版式校验。
